## Проверки

#### BEH-01: `mt add <magnet>` добавляет закачку и выходит с кодом 0
Запустить `mt add magnet:?xt=urn:btih:...` на локальном трекере/пире. Команда печатает имя
закачки и завершается с кодом 0, а последующий `mt` (list по сокету) показывает эту запись
в списке демона.
- **checked_by**: `kind: pytest` `target: tests/test_engine.py::test_add_magnet_exit_zero_and_listed`
**Критерии:** FR-01/1

#### BEH-02: `mt add <файл.torrent>` добавляет закачку из локального файла
Передать путь к `.torrent`-файлу вместо magnet-ссылки. Закачка заводится из прочитанного
metainfo, код выхода 0, запись видна в списке демона; несуществующий путь даёт ненулевой
код и сообщение в stderr.
- **checked_by**: `kind: pytest` `target: tests/test_engine.py::test_add_torrent_file`
**Критерии:** FR-01/2

#### BEH-03: При пустом конфиге файлы кладутся в папку по умолчанию
Удалить `~/.config/mt/config.toml` (или оставить его без ключа `download_dir`) и добавить
закачку. Команда отрабатывает без ошибок и без предварительной настройки, а файлы торрента
появляются в `~/Downloads`, каталог при необходимости создаётся.
- **checked_by**: `kind: pytest` `target: tests/test_config.py::test_default_download_dir`
**Критерии:** FR-01/3, FR-08/1

#### BEH-04: Путь из конфига применяется к новым закачкам
Записать в `config.toml` ключ `download_dir` с другим каталогом и добавить закачку, не
перезапуская демона. Файлы новой закачки оказываются в заданном каталоге, а её запись в
состоянии демона содержит этот же путь.
- **checked_by**: `kind: pytest` `target: tests/test_config.py::test_config_download_dir_applies`
**Критерии:** FR-08/2

#### BEH-05: Три закачки подряд идут одновременно, без очереди
Выполнить три `mt add` подряд. В ближайшем снапшоте состояния все три записи имеют статус
«качается» одновременно, ни одна не ждёт освобождения слота.
- **checked_by**: `kind: pytest` `target: tests/test_engine.py::test_three_adds_all_downloading`
**Критерии:** FR-02/1

#### BEH-06: Три закачки видны в TUI тремя строками
Подать в модель TUI снапшот с тремя активными закачками. Отрисованная таблица содержит
ровно три строки списка — по одной на закачку.
- **checked_by**: `kind: pytest` `target: tests/test_tui.py::test_three_rows`
**Критерии:** FR-02/2

#### BEH-07: Демон живёт после закрытия терминала клиента
Запустить `mt add` из процесса-оболочки и закрыть её (клиент завершён, управляющий
терминал закрыт). Процесс демона остаётся жив, не получает SIGHUP, и скачанные байты в
следующих снапшотах продолжают расти.
- **checked_by**: `kind: pytest` `target: tests/test_daemon_lifecycle.py::test_daemon_survives_client_terminal_close`
**Критерии:** FR-03/1

#### BEH-08: Демон поднимается сам при первой команде `mt add`
При отсутствующем сокете и незапущенном демоне выполнить `mt add`. Клиент сам стартует
`mt daemon` отдельной сессией, дожидается появления сокета и возвращает код 0; ручной
команды запуска не требуется, два параллельных `mt add` порождают ровно один демон.
- **checked_by**: `kind: pytest` `target: tests/test_daemon_lifecycle.py::test_daemon_autospawn_on_first_add`
**Критерии:** FR-03/2

#### BEH-09: После kill демона незавершённые закачки возобновляются сами
Убить демона на недокачанном торренте и запустить роль демона снова. Записи со статусом
`downloading` поднимаются из сохранённого metainfo автоматически, без команды пользователя,
и снова переходят в состояние «качается».
- **checked_by**: `kind: pytest` `target: tests/test_daemon_lifecycle.py::test_resume_after_kill_without_user_command`
**Критерии:** FR-04/1

#### BEH-10: После перезагрузки машины закачки возобновляются без команды
Перезагрузить машину с незавершённой закачкой. Демон поднимается средствами платформы
(LaunchAgent на macOS, user-unit systemd с linger на Linux) и сам возобновляет закачки —
пользователь ничего не вводит.
- **checked_by**: `kind: manual` `target: docs/manual/reboot-resume.md`
**Критерии:** FR-04/1

#### BEH-11: Процент после возобновления не ниже, чем был до остановки
Запомнить процент перед остановкой демона, перезапустить его и дождаться первого снапшота.
Процент не меньше прежнего — проверенные куски берутся из карты кусков и не качаются заново.
- **checked_by**: `kind: pytest` `target: tests/test_daemon_lifecycle.py::test_progress_not_lower_after_resume`
**Критерии:** FR-04/2

#### BEH-12: `mt` и `mt tui` показывают имя, процент и скорость
Запустить клиент без аргументов и с подкомандой `tui`. Оба открывают одно и то же окно со
списком, где для идущих закачек выведены имя, процент и скорость.
- **checked_by**: `kind: pytest` `target: tests/test_tui.py::test_list_columns`
**Критерии:** FR-05/1

#### BEH-13: Уже скачанные файлы видны в том же списке
Подать снапшот, где часть записей имеет статус `done`. Они отрисованы в той же таблице, что
и идущие закачки, со статусом «готово» и 100%.
- **checked_by**: `kind: pytest` `target: tests/test_tui.py::test_done_entries_listed`
**Критерии:** FR-05/2

#### BEH-14: Прогресс в окне обновляется сам, без нажатий
Отправить в TUI несколько последовательных снапшотов подписки, не подавая ввода с
клавиатуры. Отрисовка меняется на каждом снапшоте — проценты и скорости обновляются сами.
- **checked_by**: `kind: pytest` `target: tests/test_tui.py::test_snapshot_refresh_without_input`
**Критерии:** FR-05/3

#### BEH-15: Удалённый с диска файл пропадает из состояния и из снапшота
Удалить все файлы скачанного торрента из папки загрузок. Watcher замечает пропажу, запись
исчезает из `state.json` и из ближайшего снапшота, который уходит в TUI.
- **checked_by**: `kind: pytest` `target: tests/test_watcher.py::test_deleted_file_removed_from_state_and_snapshot`
**Критерии:** FR-06/1

#### BEH-16: Пропажа записи происходит без перезапуска демона
Удалить файлы при работающем демоне и не трогать его процесс. Тот же PID демона отдаёт
снапшот уже без записи, а ещё активный торрент выброшен из движка.
- **checked_by**: `kind: pytest` `target: tests/test_watcher.py::test_removal_on_live_daemon`
**Критерии:** FR-06/2

#### BEH-17: На 100% закачка переходит в «готово», соединения закрываются
Докачать торрент до конца. Статус записи становится `done`, торрент выбрасывается из
движка (`Drop`), список соединений с пирами по нему пуст.
- **checked_by**: `kind: pytest` `target: tests/test_engine.py::test_complete_sets_done_and_drops`
**Критерии:** FR-07/1

#### BEH-18: После завершения исходящий трафик по торренту — ноль
Подключиться к завершённому торренту сторонним пиром и запросить блоки. Движок настроен без
раздачи, счётчик отданных байт по этому торренту остаётся нулевым.
- **checked_by**: `kind: pytest` `target: tests/test_engine.py::test_no_upload_after_done`
**Критерии:** FR-07/2

#### BEH-19: Один и тот же набор команд отрабатывает на macOS и на Linux
Прогнать `mt add` и TUI на обеих системах из одного и того же бинаря-сборки. Пути конфига,
состояния и сокета разрешаются одинаково, вывод и коды возврата совпадают.
- **checked_by**: `kind: manual` `target: docs/manual/cross-platform.md`
**Критерии:** FR-09/1

#### BEH-20: Демон переживает отключение ssh-сессии на Linux
Добавить закачку по ssh на Linux-машине и разорвать сессию. Демон остаётся жив (linger
включён), прогресс продолжает расти, при новом входе закачка видна в TUI.
- **checked_by**: `kind: manual` `target: docs/manual/ssh-detach.md`
**Критерии:** FR-09/2

## Задачи

#### DT-01: Каркас бинаря, пути, конфиг, состояние и IPC · type: implement · owner: dev
scenarios: [BEH-03, BEH-04, BEH-19]
depends_on: []
parallel_group: solo
**Решения дизайна:** D-02, D-04, D-05, D-06, D-15, D-16
Разбор argv и выбор роли, общий слой путей (XDG с запасом `~/.config`, `~/.local/state`),
чтение необязательного TOML с `download_dir`/`listen_port` и значениями по умолчанию,
`state.json` с атомарной записью, NDJSON-протокол `add/list/subscribe` и unix-сокет 0600
с `flock`. Торрент-движка, TUI и автозапуска здесь нет.

#### DT-02: Движок закачки: add, параллельность, завершение без раздачи · type: implement · owner: dev
scenarios: [BEH-01, BEH-02, BEH-05, BEH-17, BEH-18]
depends_on: [DT-01]
parallel_group: solo
**Решения дизайна:** D-01, D-09, D-10, D-13, D-14
Обёртка над anacrolix/torrent: подкоманда `add`, различающая magnet и путь к `.torrent`,
сохранение копии metainfo, заведение торрента в движок без очереди, сбор снапшотов
прогресса и скорости, DHT/трекеры/PEX на случайном порту, `Seed=false` и `Drop()` с
`event=stopped` при 100%.

#### DT-03: Жизненный цикл демона: самозапуск, автозапуск ОС, возобновление · type: implement · owner: dev
scenarios: [BEH-07, BEH-08, BEH-09, BEH-10, BEH-11, BEH-20]
depends_on: [DT-02]
parallel_group: solo
**Решения дизайна:** D-03, D-07, D-08
Самозапуск `mt daemon` из клиента отдельной сессией с ожиданием сокета до 5 секунд,
восстановление записей `downloading` из metainfo и карты кусков на каждом старте,
регистрация LaunchAgent на macOS и user-unit systemd с `enable-linger` на Linux с
предупреждением в лог при неудаче.

#### DT-04: Слежение за диском и удаление пропавших записей · type: implement · owner: dev
scenarios: [BEH-15, BEH-16]
depends_on: [DT-02]
parallel_group: solo
**Решения дизайна:** D-11
Подписка fsnotify на каталог загрузок плюс `stat`-опрос файлов всех записей раз в 5 секунд;
если ни одного файла торрента не осталось, запись удаляется из `state.json` и из движка на
живом демоне, следующий снапшот уходит без неё.

#### DT-05: TUI со списком закачек и скачанного · type: implement · owner: dev
scenarios: [BEH-06, BEH-12, BEH-13, BEH-14]
depends_on: [DT-02]
parallel_group: solo
**Решения дизайна:** D-12
Клиент `mt` / `mt tui` на bubbletea: подписка на снапшоты и перерисовка одной таблицы с
колонками имя, статус, процент, скорость; завершённые — в том же списке со статусом
«готово». Клавиши только навигационные и `q`, TUI ничего не меняет.
