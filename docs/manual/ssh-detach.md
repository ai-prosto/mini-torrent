# Ручная проверка BEH-20: демон переживает отключение ssh-сессии на Linux

Проверяет FR-09/2: демон запускается отдельной сессией (`setsid`, D-03) и
не привязан к ssh-сессии клиента; `loginctl enable-linger` (D-08) не даёт
systemd убить user-юниты и пользовательские процессы при выходе последней
сессии. Разрыв ssh не останавливает закачку.

## Подготовка

На Linux-машине, доступной по ssh:

```sh
uv sync            # или установить пакет: uv pip install .
```

Понадобится торрент, качающийся заметное время (минуты).

## Шаги

1. **Вход и добавление.** Зайти по ssh и выполнить
   `uv run mt add <magnet>` — демон поднимется сам. Проверить linger:
   `loginctl show-user $USER -p Linger` печатает `Linger=yes`
   (включается демоном при первом старте; при неудаче — предупреждение
   в `~/.local/state/mt/mt.log`).

2. **Запомнить прогресс.** `uv run mt` — закачка `downloading`,
   запомнить процент. Запомнить pid демона:
   `cat ~/.local/state/mt/mt.lock`.

3. **Разрыв сессии.** Закрыть ssh жёстко: `~.` (escape-последовательность
   ssh) или убить локальный ssh-клиент — именно разрыв, а не аккуратный
   `exit`. Подождать 1–2 минуты.

4. **Новый вход.** Зайти по ssh снова и проверить:
   - демон жив, pid не изменился: `kill -0 $(cat ~/.local/state/mt/mt.lock)`
     выходит с кодом 0;
   - `uv run mt` показывает ту же закачку, процент выше запомненного —
     прогресс рос, пока сессии не было;
   - в `mt.log` нет записей о получении SIGHUP или перезапуске.

## Критерий зелёности

После разрыва ssh-сессии демон остался жив с тем же pid, процент закачки
вырос за время отсутствия, при новом входе список виден как ни в чём не
бывало.
