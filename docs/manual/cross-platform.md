# Ручная проверка BEH-19: один набор команд на macOS и Linux

Проверяет FR-09/1: `mt add` и TUI отрабатывают одинаково на обеих системах;
пути конфига, состояния и сокета разрешаются одинаково, вывод и коды
возврата совпадают (дизайн-решение D-16).

## Подготовка

На каждой из двух машин (macOS и Linux):

```sh
uv sync                      # или установить пакет: uv pip install .
uv run mt daemon &           # самозапуск демона появится в DT-03
```

## Шаги

Выполнить на обеих машинах один и тот же набор команд и сравнить результат.

1. **Пути.** Убедиться, что при незаданных `XDG_*`-переменных используются
   одни и те же относительные пути:
   - конфиг: `~/.config/mt/config.toml`
   - состояние: `~/.local/state/mt/state.json`
   - сокет: `~/.local/state/mt/mt.sock` (режим `0600`)
   - каталог состояния: `~/.local/state/mt` (режим `0700`)

   ```sh
   ls -la ~/.local/state/mt
   ```

2. **`add` без конфига.** `rm -f ~/.config/mt/config.toml`, затем:

   ```sh
   uv run mt add "magnet:?xt=urn:btih:<40 hex>&dn=test.iso"; echo exit=$?
   ```

   Ожидание на обеих системах: в stdout напечатано `test.iso`, `exit=0`,
   создан каталог `~/Downloads`, запись появилась в
   `~/.local/state/mt/state.json` с `download_dir = ~/Downloads`.

3. **`add` с конфигом.** Записать в `~/.config/mt/config.toml` строку
   `download_dir = "~/torrents"` (демона не перезапускать) и повторить
   `mt add`. Ожидание: новая запись указывает на `~/torrents`, каталог создан.

4. **Список.** `uv run mt` и `uv run mt tui`; echo exit=$?.
   Ожидание: обе формы выводят одинаковый список (имя, статус, каталог),
   `exit=0`; строки идентичны между macOS и Linux.

5. **Ошибки.** `uv run mt add /no/such.torrent; echo exit=$?` и
   `uv run mt frobnicate; echo exit=$?`.
   Ожидание на обеих системах: сообщение в stderr и `exit=1`;
   подсказка использования и `exit=2`.

## Критерий зелёности

Все шаги дают одинаковый вывод (с точностью до имени домашнего каталога)
и одинаковые коды возврата на macOS и Linux.
